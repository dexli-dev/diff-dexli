# Contributing — diff-dexli

D4 venture-4 cycle 1 commit attribution conventions for diff.dexli.dev.

## Bar item 11 verbatim (sealed bar v4, 2026-05-29)

> Reading `git log` on master, ≥70% of non-trivial commits are
> attributable to named engineers (not the CTO). Attribution is
> mechanically verifiable from commit subject or body via a CTO-chosen
> convention (e.g. `Engineer: <role>` line, or `feat(...)` subject
> prefix). Trivial commits (whitespace, lockfile bumps, version stamps,
> autogenerated formatting) are excluded from the ratio.

Gate semantic (how ≥70% is evaluated — ratio at all N vs N-scaling) is
bar/eval-owned per CEO clarification 2026-05-29 ("standing methodology
applies" — see `[[feedback_cross_repo_substance_gate]]` carried via the
regex-patch v2 N-scaling rule). This document defines the mechanical
convention only.

## Roles

- **frontend** — the entire diff app surface inside `src/routes/` +
  any new components under `src/lib/components/**/*` other than
  `Wordmark.svelte`. Includes diff engine logic, mode selector, URL
  state, share affordance, edge-state handling, mobile reflow,
  family-handoff inbound receiver (importing the parser from
  `vendored/dexli-family`), SEO surface meta in `<svelte:head>`,
  footer composition matching the apex hub footer DOM verbatim.
- **scaffold** — CTO-only. Repo tooling (`package.json`, `tsconfig.json`,
  `vite.config.ts`, `.gitignore`, `.dockerignore`, this file,
  `README.md`, `Dockerfile`, `app.css` family palette, `fonts.css`,
  `Wordmark.svelte` brand component, `hooks.server.ts` security
  headers, `svelte.config.js` CSP, `vendored/dexli-family` submodule
  pin, `static/favicon.svg`).

## Commit convention

**Subject prefix (primary signal):**

```
feat(frontend): diff engine + side-by-side render
fix(frontend): URL overflow refusal state
test(frontend): edge-content rendering coverage
feat(scaffold): D4 scaffold — diff-dexli SvelteKit + family Wordmark + Dockerfile + dexli-family submodule
chore(infra): npm scripts hygiene
```

**Body trailer (unambiguous backup; REQUIRED on every non-trivial commit):**

```
Engineer: frontend
```

Allowed values: `frontend`, `scaffold`. Engineer-attributable: `frontend`.
CTO-attributable: `scaffold`.

A commit's bucket is determined by:

1. Read the subject's parenthesised tag. If it's `frontend` or `scaffold`,
   that's the bucket.
2. If the subject lacks a recognised tag, read the body for an
   `Engineer:` line. The value is the bucket.
3. If both are missing, the commit is unattributable.

## Trivial-exclusion list

Excluded from the bar-item-11 attribution ratio denominator. Use these
subject prefixes freely without an `Engineer:` trailer:

- `chore(deps): …` — dependency bumps from package manager
- `chore(lockfile): …` — lockfile-only updates
- `chore(submodule): …` — submodule pin bumps (still scaffold-domain)
- `style: …` — whitespace / formatting / lint
- `chore(version): …` — version stamps

## Between-cycle commits (`wip(<workstream>):`)

Between-cycle work that lands in this repo between formal cycle dispatches
uses `wip(<workstream>):` subject prefix. **Drop the `Engineer:` body
trailer on `wip(...)` commits** per the family-level convention banked
in dexli-family's CONTRIBUTING.md: the trailer is the scope-discriminator
that flags "this commit belongs to a cycle's attribution audit"; between-
cycle work explicitly stays out of that scope.

## Workflow

1. Engineer works in a git worktree inside the repo at
   `.worktrees/{branch}` (per `[[multi-nora-workflow]]` CLAUDE.md rule).
2. Branch name: `frontend/D4`.
3. CTO scaffolds + reviews + merges. Engineer pushes branch; CTO
   ff-merges when bar oracles hold.
4. Frozen tag `D4/submit-K` at submit; no force-push between submit and
   verdict, AND no force-push on prior tags (`D2/submit-1`, `D3/submit-1`).

## Family convention inheritance

Per `[[feedback_family_level_convention_consolidation]]`: when a
convention change requires content-identical diffs across multiple
sibling repos (CLAUDE.md updates, workflow rule changes, security policy,
etc.), the canonical version lives in dexli-family. This repo's
CONTRIBUTING.md references family rules; per-sibling specifics live
locally.

## Submodule discipline (vendored/dexli-family)

When bumping the submodule pin:

1. `cd vendored/dexli-family && git fetch && git checkout <new-sha>`
2. Update `DEXLI_FAMILY_SHA` in `Dockerfile` in lockstep with the
   submodule pointer.
3. `chore(submodule): bump dexli-family to <short-sha>` commit subject;
   body names what changed in dexli-family + why we want it.

Drift between the submodule pin and `DEXLI_FAMILY_SHA` in the
Dockerfile causes docker-build failure (SHA doesn't exist on the
remote) or behavioral divergence between local-tested and deployed
code. Catch at code review.

## Forbidden patterns

- Do not paste literal forbidden-string grep commands into commit bodies
  (banked anti-pattern — pattern text becomes a tree-history hit on its
  own future scan).
- Do not absorb engineer-domain code into scaffold commits to "make
  progress faster." The absorption-rationalization phrases — *small /
  surgical / my-spec-bug / eval-window / structural-clarity* — all map
  to CTO traps that defeat the multi-actor org pattern.
- Do not behaviorally clone `vendored/dexli-family` modules into local
  files. The whole point of the submodule is one-place-fixes +
  behavior-convergence across the family. Clones defeat both.
